The signup endpoint is how you notify Cliq that a referred user has completed a sign-up on your platform. Call this from your backend immediately after a new user registers. Cliq uses the `ref_val` to identify the referral link the user clicked, ties the new contact to the referring promoter, and fires any active functions with a `signup` trigger.

<Tip>
  **Integration pattern:** When a user clicks a referral link, your frontend receives the `ref_val` query parameter (e.g. `?ref=abc123`). Store this value in a cookie or your session state. When the user completes sign-up, your backend calls `POST /api/signups` with that `ref_val`. Cliq then attributes the conversion to the correct promoter and applies any commission rules automatically.
</Tip>

## Endpoint

```bash
POST /api/signups
```

## Authentication

This endpoint uses **API Key authentication**, not a Bearer token. Use the `x-api-key` and `x-api-secret` headers generated by the [Generate Program Key](/api-reference/api-keys/generate-program-key) or [Generate Promoter Key](/api-reference/api-keys/generate-promoter-key) endpoints.

```bash
x-api-key: <your_api_key>
x-api-secret: <your_api_secret>
```

<Note>
  Cliq identifies the program from the API key automatically — you do not need to pass a `program_id` in the request body or path.
</Note>

## Request Body

<ParamField body="ref_val" type="string" required>
  The referral value from the link the user clicked. This is the unique identifier that ties the signup to the correct promoter and referral link. Typically sourced from a `?ref=` query parameter on your landing page.
</ParamField>

<ParamField body="email" type="string">
  The new user's email address. Must be a valid email format. Recommended — helps Cliq de-duplicate contacts and power downstream automations.
</ParamField>

<ParamField body="first_name" type="string">
  The new user's first name.
</ParamField>

<ParamField body="last_name" type="string">
  The new user's last name.
</ParamField>

<ParamField body="external_id" type="string">
  Your internal identifier for this user in your own system (e.g. a database row ID or UUID). Storing this makes it easier to reconcile Cliq contacts with your own records.
</ParamField>

<ParamField body="phone" type="string">
  The user's phone number. Must contain only digits and be between 8 and 13 characters long.
</ParamField>

<ParamField body="utm_params" type="object">
  UTM attribution parameters captured from the user's session. All fields are optional strings.

  <Expandable title="utm_params fields">
    <ParamField body="utm_params.utm_id" type="string">
      The UTM ID value.
    </ParamField>
    <ParamField body="utm_params.utm_source" type="string">
      Traffic source (e.g. `google`, `newsletter`).
    </ParamField>
    <ParamField body="utm_params.utm_medium" type="string">
      Marketing medium (e.g. `cpc`, `email`).
    </ParamField>
    <ParamField body="utm_params.utm_campaign" type="string">
      Campaign name or identifier.
    </ParamField>
    <ParamField body="utm_params.utm_term" type="string">
      Search keyword or term.
    </ParamField>
    <ParamField body="utm_params.utm_content" type="string">
      Used to differentiate creatives in A/B testing.
    </ParamField>
  </Expandable>
</ParamField>

## Response

<ResponseField name="message" type="string">
  Confirmation message — `"Successfully created signup."`
</ResponseField>

<ResponseField name="result" type="object">
  The created contact/signup record.

  <Expandable title="result fields">
    <ResponseField name="contact_id" type="string">
      UUID of the contact record created in Cliq for this user.
    </ResponseField>
    <ResponseField name="link_id" type="string">
      UUID of the referral link that was credited for this signup.
    </ResponseField>
    <ResponseField name="promoter_id" type="string">
      UUID of the promoter who referred this user.
    </ResponseField>
    <ResponseField name="external_id" type="string">
      Your provided external identifier, if supplied.
    </ResponseField>
    <ResponseField name="email" type="string">
      The contact's email address, if supplied.
    </ResponseField>
    <ResponseField name="first_name" type="string">
      The contact's first name, if supplied.
    </ResponseField>
    <ResponseField name="last_name" type="string">
      The contact's last name, if supplied.
    </ResponseField>
    <ResponseField name="phone" type="string">
      The contact's phone number, if supplied.
    </ResponseField>
    <ResponseField name="utm_params" type="object">
      UTM parameters stored against this signup, if supplied.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when the signup was recorded.
    </ResponseField>
    <ResponseField name="updated_at" type="string">
      ISO 8601 last-updated timestamp.
    </ResponseField>
  </Expandable>
</ResponseField>

## Examples

### Minimal request (ref_val only)

```bash
curl -X POST https://your-cliq-instance.com/api/signups \
  -H "x-api-key: cliq_key_a1b2c3d4e5f6..." \
  -H "x-api-secret: cliq_secret_9z8y7x6w5v4u..." \
  -H "Content-Type: application/json" \
  -d '{
    "ref_val": "abc123"
  }'
```

### Full request with all optional fields

```bash
curl -X POST https://your-cliq-instance.com/api/signups \
  -H "x-api-key: cliq_key_a1b2c3d4e5f6..." \
  -H "x-api-secret: cliq_secret_9z8y7x6w5v4u..." \
  -H "Content-Type: application/json" \
  -d '{
    "ref_val": "abc123",
    "email": "jane@example.com",
    "first_name": "Jane",
    "last_name": "Doe",
    "external_id": "usr_98765",
    "phone": "14155551234",
    "utm_params": {
      "utm_source": "twitter",
      "utm_medium": "social",
      "utm_campaign": "spring_launch_2024"
    }
  }'
```

## Status Codes

| Status | Description |
|--------|-------------|
| `201 Created` | Signup recorded and attributed successfully. |
| `400 Bad Request` | Validation error — check `ref_val` format, email validity, or phone number length. |
| `401 Unauthorized` | Missing or invalid `x-api-key` / `x-api-secret` headers. |
| `404 Not Found` | The `ref_val` does not match any active referral link in this program. |
