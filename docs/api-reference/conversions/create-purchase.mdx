The purchase endpoint is how you notify Cliq that a referred user has completed a purchase on your platform. Call this from your backend immediately after a successful transaction is confirmed. Cliq uses the `ref_val` to attribute the purchase to the correct referral link and promoter, then fires any active functions with a `purchase` trigger — typically generating a commission for the referring promoter.

<Tip>
  **Integration pattern:** When a user clicks a referral link, capture the `ref_val` from the query string (e.g. `?ref=abc123`) and store it in your session or database. When the user completes a purchase, your backend calls `POST /api/purchases` with that `ref_val` and the transaction details. Cliq attributes the sale and applies commission rules automatically — your promoter's dashboard updates in real time.
</Tip>

## Endpoint

```bash
POST /api/purchases
```

## Authentication

This endpoint uses **API Key authentication**, not a Bearer token. Use the `x-api-key` and `x-api-secret` headers generated by the [Generate Program Key](/api-reference/api-keys/generate-program-key) or [Generate Promoter Key](/api-reference/api-keys/generate-promoter-key) endpoints.

```bash
x-api-key: <your_api_key>
x-api-secret: <your_api_secret>
```

<Note>
  Cliq identifies the program from the API key automatically — you do not need to pass a `program_id` in the request body or path.
</Note>

## Request Body

<ParamField body="ref_val" type="string" required>
  The referral value from the link the user clicked. This ties the purchase to the correct promoter and referral link. Typically sourced from a `?ref=` query parameter stored at session start.
</ParamField>

<ParamField body="amount" type="number" required>
  The purchase amount. Must be a non-negative number (≥ 0). Used by percentage-based commission functions to calculate the commission value. Use your standard currency unit (e.g. dollars, not cents).
</ParamField>

<ParamField body="item_id" type="string" required>
  Your internal identifier for the purchased product or service (e.g. a SKU, plan ID, or order ID). This is stored with the purchase record for reporting and reconciliation.
</ParamField>

<ParamField body="email" type="string">
  The buyer's email address. Must be a valid email format. Recommended for contact matching and downstream automations.
</ParamField>

<ParamField body="first_name" type="string">
  The buyer's first name.
</ParamField>

<ParamField body="last_name" type="string">
  The buyer's last name.
</ParamField>

<ParamField body="external_id" type="string">
  Your internal identifier for this user or transaction. Useful for reconciling Cliq records with your own database.
</ParamField>

<ParamField body="phone" type="string">
  The buyer's phone number. Must contain only digits and be between 8 and 13 characters long.
</ParamField>

<ParamField body="utm_params" type="object">
  UTM attribution parameters captured from the user's session. All fields are optional strings.

  <Expandable title="utm_params fields">
    <ParamField body="utm_params.utm_id" type="string">
      The UTM ID value.
    </ParamField>
    <ParamField body="utm_params.utm_source" type="string">
      Traffic source (e.g. `google`, `newsletter`).
    </ParamField>
    <ParamField body="utm_params.utm_medium" type="string">
      Marketing medium (e.g. `cpc`, `email`).
    </ParamField>
    <ParamField body="utm_params.utm_campaign" type="string">
      Campaign name or identifier.
    </ParamField>
    <ParamField body="utm_params.utm_term" type="string">
      Search keyword or term.
    </ParamField>
    <ParamField body="utm_params.utm_content" type="string">
      Used to differentiate creatives in A/B testing.
    </ParamField>
  </Expandable>
</ParamField>

## Examples

### Minimal request (required fields only)

```bash
curl -X POST https://your-cliq-instance.com/api/purchases \
  -H "x-api-key: cliq_key_a1b2c3d4e5f6..." \
  -H "x-api-secret: cliq_secret_9z8y7x6w5v4u..." \
  -H "Content-Type: application/json" \
  -d '{
    "ref_val": "abc123",
    "amount": 99.00,
    "item_id": "plan_pro_monthly"
  }'
```

### Node.js integration example

```javascript
// After a successful checkout, report the purchase to Cliq
async function reportPurchaseToCliq({ refVal, amount, itemId, customer }) {
  const response = await fetch('https://your-cliq-instance.com/api/purchases', {
    method: 'POST',
    headers: {
      'x-api-key': process.env.CLIQ_API_KEY,
      'x-api-secret': process.env.CLIQ_API_SECRET,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      ref_val: refVal,
      amount: amount,
      item_id: itemId,
      email: customer.email,
      first_name: customer.firstName,
      last_name: customer.lastName,
      external_id: customer.id,
    }),
  });

  if (!response.ok) {
    const error = await response.json();
    console.error('Failed to report purchase to Cliq:', error);
    // Handle gracefully — don't block the user's purchase flow
    return null;
  }

  return response.json();
}
```

<Note>
  Always report conversions to Cliq **after** your own transaction has been confirmed successful. Handle Cliq API errors gracefully — a failure to report to Cliq should not block or reverse a user's purchase in your system.
</Note>

## Status Codes

| Status | Description |
|--------|-------------|
| `201 Created` | Purchase recorded and attributed successfully. |
| `400 Bad Request` | Validation error — check `amount` (must be ≥ 0), `item_id` (required), phone number format, or email format. |
| `401 Unauthorized` | Missing or invalid `x-api-key` / `x-api-secret` headers. |
| `404 Not Found` | The `ref_val` does not match any active referral link in this program. |
